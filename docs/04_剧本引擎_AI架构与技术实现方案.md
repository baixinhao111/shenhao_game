# 04. 剧本引擎、DeepSeek AI 架构与技术实现方案

> **架构原则**：面向小圈子自建服务器、单机一键部署、极低运维成本、极高内容扩展性。把**“代码引擎”**与**“游戏内容（剧本/红颜/产业/活动）”**彻底分离，确保你以后能像更新小说一样持续给游戏加新章节、新红颜和限时活动。

---

## 一、推荐技术栈（轻量、现代、单机稳如老狗）

| 层级 | 选型方案 | 选型理由 |
| :--- | :--- | :--- |
| **前端** | **React 18 + TypeScript + Vite + Tailwind CSS + Framer Motion + Zustand** | 组件化极佳，动效丝滑，Mobile-First + PWA 配置零门槛；打包后纯静态文件可由后端直接托管，**前后端同端口运行，免去跨域折腾** |
| **后端** | **Node.js (Fastify / Express) + TypeScript** | 与前端全栈同语言（共享数值与剧本 TypeScript 类型定义），写 JSON 剧本解析、状态机和 DeepSeek SSE/JSON 接口极度顺手 |
| **数据库** | **SQLite (`better-sqlite3` / Prisma 或 Drizzle ORM)** | 零外部数据库安装运维，小圈子几十上百人并发绰绰有余，全服存档就是一个 `.db` 文件，定时复制即可秒级备份；未来真要上万人可平滑迁移 PostgreSQL |
| **AI 接口** | **DeepSeek API（OpenAI SDK 兼容）** | 选用性价比最高的 `deepseek-chat`（原生支持上下文自动缓存 Context Caching），中文都市恋爱/爽剧语感极强，小圈子高频聊天月成本极低 |
| **部署方式** | **单机 Docker Compose 或 Node + PM2 + Nginx/Caddy（HTTPS）** | 买/用现有个人服务器，配好域名或直接 IP 端口访问，点链接秒开 |

## 二、内容热插拔架构（怎么实现不断加剧本、加红颜、开活动）

项目目录结构将**逻辑代码**与**配置数据**完全解耦：

```text
shuang_game/
├── docs/                     # Phase 0 规划与设计文档
├── content/                  # ★ 纯数据内容包（支持后台热重载，无需改代码！）
│   ├── maps/                 # 城市地图与片区配置：haicheng.json, district_events.json ...
│   ├── stories/              # 剧本库：prologue.json, vol1_ch01.json ...
│   ├── events/               # 限时活动配置：event_cruise_01.json ...
│   ├── heroines/             # 红颜人设、昼夜行踪、羁绊与 AI Prompt 配置
│   ├── properties.json       # 多处房产配置表（所属区域、主宅加成、租金、精装、可入住槽位）
│   ├── businesses.json       # 产业配置表
│   ├── assets_catalog.json   # 豪车/载具/藏品图鉴与套装表
│   ├── gifts.json            # 礼物与暴击返现配置
│   └── skills.json           # 系统词条技能树配置
├── client/                   # 手机端 React + Vite 前端
└── server/                   # Node.js 后端（存档、数值、AI 代理、GM 后台）
```

## 三、DeepSeek AI NPC 实时聊天深度架构

要让 AI 红颜既有“活人感 + 记性好”，又**省 Token、稳输出、防作弊**，采用以下四层设计：

### 1. 模型与成本优化策略
- **日常对话主模型**：`deepseek-chat`（性价比极高，且支持 **Prompt 静态前缀自动缓存**）。
- **记忆提炼任务**：复用 `deepseek-chat`，每满 **16 轮对话**异步触发一次摘要压缩（不阻塞玩家聊天气泡）。
- **为什么把固定人设放最前面？** DeepSeek 对完全一致的 System Prompt 前缀会自动触发缓存降价，因此我们把**不变的世界观 + 角色固定人设 + JSON 输出协议**放 System Prompt 顶部，把**动态游戏状态**放用户消息前的上下文块里，大幅降低小圈子长期聊天的 API 费用！

### 2. 四段式上下文组装结构

```text
[Block 1: 静态系统提示词 — 命中 DeepSeek Prefix Cache]
  - 你正在扮演《天枢神豪》中的角色：苏清婉（性格、口癖、背景、雷区、边界规则）
  - 严禁跳出角色承认自己是 AI
  - 严格按指定 JSON Schema 返回回复

[Block 2: 动态游戏世界状态快照 — 后端实时从数据库注入]
  - 当前现实时间段：深夜 23:15（可自然关心玩家是不是刚应酬完）
  - 玩家所在位置与座驾：正驾驶【保时捷 911 Turbo S】来到【陆家湾金融 CBD / 或：你赠予她的外滩江景大平层客厅】
  - 玩家昵称：陆沉 | 社会阶层：海城名流 | 总身价：¥1.2亿 | 当前主居所：云顶半山庄园
  - 当前主线进度：已通关第2卷第10章（刚刚收购星耀传媒）
  - 玩家刚购入的新资产：私人游艇「海神号」
  - 你们当前关系：Lv.4 暧昧拉扯（好感度 420/600）| 房产关系：已获赠【外滩江景大平层】钥匙
  - 近期互动记录：玩家 10 分钟前刚送你一条【梵克雅宝四叶草项链】
  - 修罗场状态：玩家今天刚给沈琉璃刷了 500 万礼物（可酌情微微吃醋）

[Block 3: 长期记忆胶囊（最多 8～12 条精炼事实）]
  - "第3天雨夜，他带我去巷口吃了碗热阳春面，说我不必总端着架子"
  - "在董事局危机时，他二话不说替我兜底了三千万"

[Block 4: 最近 10～12 轮原始对话历史 + 玩家本轮新消息]
```

### 3. 结构化输出协议（JSON Mode）与后端数值防刷

通过 DeepSeek 的 `response_format: { type: "json_object" }` 强制返回结构化结果：

```json
{
  "reply": "刚看到消息……项链我很喜欢，谢谢你。不过听说陆总今晚在某位大主播直播间玩得很开心？",
  "inner_thought": "其实拿到项链心跳快了半拍，但又忍不住在意他给别人花钱的事。",
  "mood": "jealous_cute",
  "affection_delta": 2,
  "trigger_moment": null
}
```

- **前端渲染**：`reply` 显示在微信气泡里；`inner_thought` 可通过玩家点击【天枢读心微光】按钮展开查看（极爽的短剧上帝视角！）；`mood` 控制聊天顶部微表情头像。
- **后端风控校验（核心安全线）**：
  1. 单条回复 `affection_delta` 强行钳制在 `[-3, +3]` 之间；
  2. 每位红颜每日通过纯 AI 聊天获得的好感上限锁死（例如 `+8 / 天`），超出后仍可畅聊但不再白嫖刷好感；
  3. 每日每玩家可配置 AI 聊天配额（例如小圈子默认 60～100 条/天，可在 GM 后台随时调）；
  4. 若 API 超时或波动，后端自动回退一条符合角色人设的“正在开会/信号不太好，稍后回你”优雅兜底消息，绝不弹窗报错破坏沉浸感。

## 四、核心数据库表设计（SQLite 精简版）

仅需 11 张核心表即可支撑全部大地图、多房产、长线养成、AI 记忆与限时活动：

1. `users`：账号、密码哈希、昵称、创建时间、是否管理员
2. `player_state`：现金、系统积分、系统等级与经验、精力与上次恢复时间戳、社会阶层、暴击充能值、主线当前进度、当前所在地图/区域 ID、当前主居所房产 ID、当前驾驶座驾 ID、已解锁系统词条 JSON
3. `player_businesses`：玩家已拥有的各产业等级、委派红颜 ID、上次离线收菜时间戳
4. `player_properties`：玩家拥有的多处房产列表（房产 ID、所属片区、精装等级、自定义冠名、获赠钥匙/入住的红颜 ID 列表、已解锁豪宅设施与展厅陈列品 JSON、上次收租时间戳）
5. `player_assets`：已拥有的豪车/载具/藏品 ID 及获取时间
6. `player_heroines`：每位红颜的解锁状态、好感度、关系等级、每日聊天已获好感、已解锁装扮、已读个人支线
7. `npc_chat_messages`：AI 私聊历史记录（含所在场景/房产上下文、inner_thought、mood、token 消耗统计）
8. `npc_memories`：各红颜的长期记忆胶囊列表
9. `social_moments`：朋友圈动态流（主体内容、配图、点赞与评论列表 JSON）
10. `player_progress`：已完成主线/支线章节 ID、每日/周常任务状态、各区域闲逛与副玩法当日记录（赌石/天使投/竞速/股市/直播）
11. `events_and_mail`：限时活动配置与开启时间、玩家活动积分与兑换记录、全服/个人 GM 福利邮件
